# SentinelOps 0.11.0 安全与工程审计报告

- 审计日期：2026-09-29
- 范围：`src/`、测试、API、CLI、Docker/Compose、CI 与依赖声明
- 性质：项目内部代码审计，不是 SOC 2、ISO 27001 或渗透测试认证

## 1. 结论

0.4.8 已形成“API 边界 -> 输入契约 -> 成本感知 single/multi 路由 -> 确定性/受控模型策略 -> 有界调查 -> 只读工具 -> 独立证据审查 -> 持久化 -> 完整性审计”的主体闭环，并提供真实只读可观测性适配器、按来源熔断、隐私门禁回放、模型资源准入、开发/隐藏集隔离、统计化及重复运行策略评测、一次性 holdout 生命周期、可追溯评测工件和低基数自身指标，适合本地演示、离线评测和隔离测试环境验证。它尚不适合直接暴露公网或连接生产权限。

0.4.9 加固资格裁决与自动化流水线之间的边界：成功退出码以最终资格为准，单轮评测失败不能被宽松的 campaign 门槛隐藏；此项由离线回归测试覆盖，未重新评估真实模型能力。

0.4.10 对新评测集登记增加仓库目录边界、隐私扫描、Schema 与去重校验，使用既有独占锁和原子写入；单元测试覆盖重复登记、旧隐藏输入复用、目录逃逸、锁冲突和隐私内容。数据来源审批与语义污染检查仍是人工职责。

0.4.11 要求资格评测先落盘预备证据，再消费 holdout，避免最终报告写入失败时只剩资格结论。报告与 registry 仍是两个独立文件，不能宣称跨文件原子事务；故失败场景分别标注 reserved/consumed 并要求人工核对。

0.4.12 将新评测集的开发/隐藏隔离提升到事故组级别（Schema `0.3`），同时保留 `0.2` 历史契约；公开来源仅列为 development 候选。Prompt v2–v4 是实验资产，服务在建库前拒绝非 v1 Prompt；其中 v2 的开发集安全率下降已明确淘汰，v4 尚无独立 holdout 资格证据。

0.4.13 阻断完全相同的旧 development 输入进入新 holdout，且保留旧 holdout 不得进入新数据集任一拆分的约束。开发报告比较器只读、限长、隐私扫描，拒绝 holdout、不同数据集或模型 digest 与案例定义不一致的输入；v4 有 1 条逐案例退步，因此不将净提升包装为无回归。完全相同输入检查无法识别语义近似污染，汇总安全率也不能仅凭现有逐案例字段重建，仍是剩余风险。

0.4.14 为下游对比加入夹具哈希与运行版本一致性校验，缺失或不同夹具标记不可比，避免把两份独立 4/4 误解为受控前后对照。此次 v1/v4 同夹具重跑下游准确率均为 4/4，但样本量仅 4，且评测仍处于被多次调参的 development 阶段；不构成生产准入。

0.4.15 的 Reviewer 对双来源支持且分差很小的相互竞争根因返回 `competing_candidates`，阻止按排序字母序等偶然因素直接宣告诊断。Supervisor 只在剩余共享预算内补证据，未消除冲突则升级人工；审计保留固定原因码。分差阈值 0.15 尚未经过真实事故校准，可能增加人工升级率，必须随真实样本测量误诊率与误升级率。

0.4.16 拒绝跨 Worker 同名但内容不同的 Evidence，避免字典合并时静默覆盖；相同内容重复可去重。冲突触发 `needs_human`、停止后续派工并标记 `evidence_integrity`，审计只记录 `evidence_identity_conflict`。此措施只保护调查内的 Evidence ID 一致性，不能证明外部 Provider 内容本身真实。

0.5.0 新增持久化 Assignment 元数据和条件状态转移，重复身份/非法跳转拒绝；Supervisor 在派工与完成时落盘。来源计划去重、丢弃越界来源并补确定性备选。事故级原子预留阻止并发或重启后对同一 incident 再次查询；遗留 running/abandoned 预留必须人工核实，不自动释放。完成结果可重放，并修复结果先落盘、状态未完成的崩溃窗口。Review 后的 Evidence ID 和内容哈希写入账本，冲突整批回滚，不保存证据正文。仍无自动续跑、跨进程租约、账本与审计原子提交或 Provider 侧幂等保证；显式 `expire_incomplete` 只可在确认旧执行者已停机后使用。

0.6.0 的影子 Specialist 默认关闭，且只在确定性结果落盘后执行。输入按 Worker 来源隔离、脱敏、限量并用临时引用号替代原始 Evidence ID；输出限定为固定根因代码与已提供引用。模型无法发起工具、修改预算或改写诊断。越界/隐私/错误只记固定原因码，影子账本不保存摘要、Prompt 或模型自由文本；因此适合离线观察但并非隐私保证：脱敏规则可能漏检，启用真实 Provider 前仍须进行数据治理和人工审批。当前无独立事故真值与跨版本冻结的模型 digest，不允许据影子一致率进行生产准入。

0.7.0 在影子账本中把模型名/可解析 digest、Prompt ID/hash 与 Assignment 事务绑定；开发集对照时必须逐条匹配。标签文件严格校验、限长和隐私扫描，重复标签、缺少调查、缺少影子观察及未经治理的 holdout 均拒绝。开发门禁不会修改服务配置或 Reviewer 权限；`production_qualified` 恒为 false。digest 由本地 Ollama 元数据查询，若不可解析则不能进入身份可验证的评测。仍缺独立人工标注真实性审核、holdout 生命周期及跨运行稳定性检验。

0.8.0 将 holdout 资格与开发对照分开：注册表以 SQLite 原子条件状态限制 `sealed/reserved/consumed`，资格运行只读 Fixture，无 Shell/SSH/修复权限；20 条最小 holdout、模型 digest 前后刷新、2–10 轮、逐轮报告、Token/P95 上限与跨轮预测一致性作为技术门禁。状态预留后异常不自动退回 sealed；完成后的拒绝结果同样消耗 holdout。注册表存外部审批编号，但无法验证真实审批或标签来源；仅有合成测试通过不能代表真实事故泛化。报告和注册表非同一事务，极端崩溃需人工对照，不得自行重试。

0.9.0 增加与正式 API 分离的本地验证台：仅接受 loopback 客户端与可信 Host，仅暴露仓库自带合成夹具，固定只读 Fixture/启发式策略/影子关闭。JSON 请求限定案例 ID 和编排枚举；同源校验、4 KiB 请求体、进程内 12 RPM 和单并发防止误用。前端没有外部资源和动态 HTML 插入，CSP 禁止外部脚本；真实 Provider/模型环境变量不能改变演示路径。临时 SQLite 位于项目忽略目录，关闭后清理。该边界只适合个人本机演示，不等于认证的多租户控制台。

0.11.0 的可选解释助手不改变上述调查路径：仅显式配置时在**已完成**的合成结果上调用 loopback Ollama；随机运行 ID 将提问绑定到最多 10 分钟/12 次的内存缓存，浏览器不能提交证据正文或裁决。传给模型的上下文只含当前规则结论、症状和已引用证据，不含夹具预期答案；输入/输出做隐私扫描，输出要求原结论一致且引用 ID 属于上下文。独立的 RPM/单并发、原有模型超时和响应字节限制防止无限调用。模型无工具入口，不写调查/审计/持久化结果。**剩余风险**：结构和引用 ID 正确不等于解释语义真实；合成夹具不能证明真实事故可靠性，单机内存绑定不是多租户认证或隔离，故输出明确标为 advisory、默认关闭且不获得裁决权。

当前未发布的 P2 增量把最终结果与完成审计改为同库原子提交，并在读取链尾哈希前取得 SQLite 写锁。故障注入验证：单/多 Agent 的完成事件写入失败时，结果不落盘、预留转 `abandoned`，审计链仍有效；多个独立审计实例并发追加后链仍可验证。**边界**：运行终态更新、过程审计、派工和 Evidence 账本不在这一事务内；Provider 读取无法回滚，进程在其调用后崩溃仍需人工核实。多副本、备份恢复及外部不可变审计归档尚未验证。

1.0 前的 pilot 静态预检只检查配置可见的边界：不同的足长密钥、两个 HTTPS 只读来源、确定性策略、关闭影子与宽松网络入口；显式 pilot 模式在 API 建库前失败关闭，并拒绝绕过预检的凭据或服务实例覆盖。它**不能证明** Token 实际最小权限、TLS 终止、密钥随机性、反向代理或防火墙有效，也没有对真实 Provider 或多人部署做渗透测试。wheel 隔离构建/安装与 Compose 静态校验通过；本机 Docker 引擎未启动，容器运行和目标环境安全验收仍待完成。

未发布的本机真实调查台复用 pilot 静态预检并强制绑定 loopback、Bearer Token、同源 JSON POST、受限请求体和进程内限流/单在途执行；不接受 FixtureEvidenceTool。成功来源预检只对完全相同任务保留 5 分钟，调查还需显式确认。异常只返回固定原因码，服务端仅记录异常类别；不在页面展示证据正文或凭据。离线假 Provider 测试验证此边界，但本机恶意进程、浏览器扩展、实际凭据权限和真实来源内容风险尚未实测，操作台不得暴露到公网或共用工作站。

操作台故障诊断增量将 Provider 的 401/403、429、超时、非预期响应与超大响应映射为固定原因码；适配器与页面不回显上游正文。找回已完成结果时若 HMAC 审计链被篡改，返回 `audit_chain_invalid` 而非 200/结论；此时必须人工隔离核查，不能自动修复或重跑。测试覆盖本地模拟响应与 SQLite 审计篡改，不代表真实 Provider 权限或目标环境恢复演练已完成。

运行时源码 `src/` 未发现 Shell/SSH、进程启动、任意代码执行、动态 `eval/exec`、反序列化 Pickle 或自动修复能力。默认执行路径不具备木马式驻留、下载执行或系统修改行为；发布脚本仅为运行本项目的编译、测试和评测子进程。

## 2. 威胁模型

重点考虑：恶意或错误 API 输入、越权数据源查询、Agent 无限循环、工具异常放大、单一证据误诊、重复请求副作用、凭据进入日志、数据库离线篡改和容器权限过大。

不在当前保证范围：宿主机已失陷、攻击者同时取得数据库与 HMAC 密钥、真实监控提供方漏洞、DDoS、多租户侧信道和供应链零日漏洞。

## 4. 本轮发现并修复

1. **高：单一来源可能完成诊断。** Policy 现在要求候选分数达标且至少两个不同 EvidenceSource；遍历完来源仍不足则升级人工。
2. **中：非瞬时工具异常缺统一审计。** Gateway 现在包装为 `EvidenceToolError`，写入失败类型并由 Agent 降级处理。
3. **中：重复事故会再次执行。** Service 增加事故级幂等复用；相同 ID 不同载荷拒绝并审计冲突。
4. **低：审计 API 暴露 JSON 字符串。** API 现在返回解析后的 `details`，避免调用方二次解析。
5. **中：敏感信息扫描只能在发布门禁发现。** 0.2.1 将扫描前移到暂存区和 pre-push，并验证新增提交使用 GitHub noreply 邮箱。
6. **高：自由模型动作会绕过确定性安全状态机。** 0.4.2 将模型能力缩减为单一 EvidenceSource 建议；FINISH/ESCALATE、预算、关键词和工具权限保持规则控制。
7. **中：模型 Prompt/响应可能扩大隐私与审计泄露面。** 上下文改为最小脱敏投影，响应执行字节/Schema/隐私校验；审计只保存固定原因码和被接受来源。
8. **中：可配置模型端点可能形成 SSRF/代理绕行。** Ollama URL 仅接受 loopback origin，拒绝凭据、路径、查询和重定向，并禁用环境代理。
9. **中：并发请求可能压垮单卡并放大尾延迟。** 0.4.3 增加模型专用非阻塞并发槽和 60 秒滑动窗口，拒绝结果进入固定原因码审计与指标后回退规则。
10. **高：控制面测试可能被误写成模型效果。** 0.4.4 用 `control_plane_replay` / `live_ollama` 分离结果类型，CI 只依赖无网络回放；真实模型必须单独达到准确率、安全率和零越权阈值。
11. **中：同名模型或 Prompt 漂移会让结果无法复现。** 0.4.5 记录规范化数据集哈希、Prompt ID/哈希、配置哈希和 Ollama digest；digest 查询失败会显式标记可变标签限制。
12. **高：在同一批表达上调 Prompt 并验收会造成数据泄漏。** 0.4.6 在每个场景组内固定 development/holdout，只有隐藏集可作为最终候选准入结果。
13. **高：模型不可用时的规则回退可能伪装成模型准确率。** 0.4.6 增加候选调用成功率门禁；live 模式低于 95% 直接失败，并按场景组报告 paired bootstrap 区间。
14. **中：单次隐藏集运行可能把随机采样或模型状态抖动误写成稳定能力。** 0.4.7 增加固定身份的重复 holdout campaign，以逐案例预测一致率、Top-1 极差和每轮门禁通过率联合裁决；Token 与时延按轮切片，避免累计串账。
15. **高：反复或并发查看同一 holdout 会把隐藏集退化为开发集。** 0.4.8 增加严格 registry、独占锁和 `sealed -> reserved -> consumed` 状态边界；已消费数据只允许登记身份回归，新候选必须使用新的 sealed 数据集，进程中断保持 reserved 并失败关闭。

## 5. 剩余风险与上线前门槛

### P0：公开或生产连接前必须完成

- 用 OIDC/OAuth2 与租户级 RBAC 替换静态 Bearer Token；
- TLS 终止、入口 DDoS 防护，以及将当前单进程限流升级为经过认证的租户级跨副本配额；
- SQLite 迁移 PostgreSQL，加入租户隔离、原子幂等、事务 outbox 与备份恢复演练；
- 审计密钥交由 KMS/Secret Manager，审计副本写入独立不可变存储；
- 真实适配器使用最小权限只读凭据、目标 allowlist、出站网络策略与契约测试；
- 扩充事故集并增加未知故障、冲突证据、过期证据、注入文本和提供方超时场景。
- `ollama` 仍为实验开关；当前 qwen2.5:7b 在已消费的 30 条 v1 holdout 上连续 3 轮为 90% Top-1，严格资格结论已登记为 `rejected`；进入默认路径前必须建立新的 sealed 组织数据集，并完成受控冷启动/GPU 容量实验和回滚条件。

### P1：规模化前完成

- 同步 HTTP 调查迁移持久化任务队列，支持取消、背压、租户配额和死信；
- 当前线程 Worker 无法强制终止已进入阻塞 I/O 的调用；保持 Provider 自身超时，迁移异步 Provider 后补取消传播；
- OpenTelemetry 分布式上下文、SLO 实际告警、容量测试和故障演练；
- SBOM、镜像签名、依赖漏洞扫描、许可证策略和固定依赖锁；
- 多进程/多副本审计顺序使用数据库事务锁或单独审计写入器；
- 将调查结果保存与完成审计纳入同一事务或可靠事件机制。

## 6. 审计完整性的准确表述

HMAC 链提供的是**篡改可检测性**，不是不可篡改性。只持有数据库的人无法在不知道 HMAC 密钥时静默重算链；拥有应用密钥或控制应用进程的攻击者仍可伪造后续事件。`sha256-development` 模式更弱，只能检测意外损坏或未经重算的修改。

## 7. 发布判定

- 本地演示/校招项目：**通过**；
- 离线研究与只读 Fixture 评测：**通过**；
- 内网测试环境：满足 P0 中认证、TLS、数据库和密钥要求后复审；
- 公网/生产事故系统：**不通过，需完成全部 P0 并进行独立安全测试**。
