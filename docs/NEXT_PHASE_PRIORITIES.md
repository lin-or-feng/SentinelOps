# SentinelOps 方向检查与优先级（2026-09-29）

## 当前判断

项目已具备有界调查、只读网关、多 Agent 派工、确定性 Reviewer、审计链、受控本地模型和影子资格评测框架。主要风险不再是“缺一个 Agent 类”，而是**能力难以直观看见**、合成/开发评测容易被误解为真实效果，以及生产化组件仍停留在路线图。应先让现有闭环可观察、可复核，再投入真实数据治理；避免继续增加没有独立证据的新模型策略。

| 优先级 | 目标 | 验收标准 | 当前状态 |
|---|---|---|---|
| P0 | 本地可视化与可复核闭环 | 四条合成事故在 single/multi/auto 下均可重新运行；页面展示派工、证据、Trace、审计及逐例门禁；失败能显式显示 | 0.9.0 已完成，本机浏览器与自动化测试通过 |
| P1 | 真实数据来源与独立评测 | 获得有授权、最小化脱敏的事故样本；独立人员标注；按事故组隔离开发/holdout；登记来源与审批证据；首次资格运行前冻结 Prompt/模型 | 0.10.0 增加只读候选预检；两条公开复盘被阻断，尚无合格独立样本，不能宣称模型泛化 |
| P2 | 运行可靠性与生产边界 | 最终结果与完成审计同库原子提交已在未发布工作区完成；仍需 Provider 超时与取消测试、多进程存储、RBAC、备份恢复演练、SLO 和真实只读 Provider 隔离验证 | 1.0 设计目标，当前不可直接生产部署 |
| P3 | 模型性能优化 | 只在 P1 数据和 P2 可观测基础上做 Prompt/模型对照；报告相同数据与版本下的准确率、安全率、P95、Token、回退率和退步案例 | 当前不应优先于数据治理 |

1–5 发布门槛的工作区进度见 [1.0 前发布资格验收](RELEASE_READINESS.md)：真实任务文件/来源预检、备份恢复、pilot 配置预检与独立 wheel 冒烟已实现；独立数据、真实只读联调、目标环境安全/容器验收仍未完成。不以版本号代替验收。

未发布工作区已增加[本机真实调查台](OPERATOR_DESK.md)，将 P0 从纯合成演示扩展到“获批真实来源可手动操作”的入口；它目前只通过假 Provider 的离线闭环与打包验证。下一项最高优先级仍是取得只读授权和一条真实事故，逐步验证来源、调查、证据引用、人工复核、审计与备份恢复。没有授权条件时不得以合成页面替代这项验收。

## 本轮取舍

0.9.0 只完成 P0 的演示与测试入口，不修改生产 API 的裁决权限，不连接外部监控，不运行真实 Ollama，也不重开已消费 holdout。演示 `4/4` 是合成夹具的工程回归值，不能替代 P1 的独立测量。P0 验收后，下一阶段先执行 P1 的数据来源/标注/隐私治理，而非直接跃迁到多租户平台。

0.10.0 执行 P1 的第一个机器预检切片：明确拒绝多事故未拆分、时间点证据缺失/过晚、分类不适配和复核凭证缺失。它只暴露数据缺口，不补造样本；下一步需要独立于开发者的标注人与有授权的同时点只读证据，随后再考虑新数据集封存。

0.11.0 增加默认关闭的只读 AI 辅助解释预览，解决“能力看不见”的交互问题，但**不改变 P1/P2 的先后顺序**：合成案例回答与严格引用只证明接口/权限边界可用，不能替代独立事故评测；AI 仍无最终诊断权。下一步优先取得可核实的同时点证据与独立标签，然后评估 AI 假设相对规则基线的收益和误诊风险。
